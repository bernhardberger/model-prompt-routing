# Worked task packets

Examples illustrate the original task contract; they are not mandatory templates
or measured cross-model comparisons. Paths and test commands are fictional and
must be resolved from the actual project before launch. Model/effort selection
remains subject to the user's choice, role defaults and applicable local policy.

## Bounded implementation

> Fix quoted commas in `src/csv.ts`; reproduction is
> `tests/fixtures/quoted-comma.csv`. Preserve the public API and existing parser
> behavior. Edit only the parser and relevant tests; add no dependencies. Run the
> project's focused parser checks. Return changed files, check results and any
> remaining blocker. Stop once this behavior and its checks pass; ask if the fix
> requires a public API change. Do not publish or deploy.

A balanced model such as Sonnet 5.5 or GPT-6.1 Sol is a reasonable starting point.
For a narrow Haiku assignment, keep the reproduction and required check explicit.
For Opus, avoid adding generic double-check or reviewer-child instructions. For
GPT, define routine autonomy and the completion bar without prescribing every
tool call. The actual authority and acceptance criteria stay identical.

## Evidence-only investigation

> Find why requests can be retried after cancellation. Inspect the cancellation
> path and its callers; make no changes. Return the causal path with file/line
> evidence, a minimal reproduction if possible, and unresolved uncertainties.
> Distinguish observed behavior from hypotheses. Stop when you can explain the
> failure or identify the exact evidence you cannot access.

Do not accidentally turn an assessment into implementation. Narrow triage suits
a smaller model when the evidence is localized; ambiguous cross-system behavior
can justify a stronger model immediately without requiring an initial failure.

## Current-source research

> Check whether the exact provider and model support cache-preserving effort
> changes. Use official documentation and the installed adapter's implementation.
> Report documented API support, implemented adapter behavior and remaining gaps
> separately, with source links or file/line evidence. Make no config changes.

Provide the exact access route and current date. An API feature announcement
does not establish subscription or harness support. Keep the researcher's output
contract if its role already defines one.

## Independent review

> Review this specified diff against the attached requirements. Report behavioral
> defects with file/line evidence, triggering conditions, likely impact and
> confidence. Include uncertain candidates explicitly as uncertain; omit pure
> style preferences. Do not edit or launch other reviewers. Return the role's
> existing verdict format and state which checks you could not perform.

When two independent reviews are authorized, send the same initial evidence to
both and withhold each other's verdicts. Subsequent packets identify unresolved
findings and materially changed behavior; do not commission the entire review
again by default. Coverage, permissions and independence do not depend on effort.

## Failure to targeted adjustment

- Stops after announcing the next step: clarify the completion condition and
  actual blockers; inspect harness continuation before adding repeated prompts.
- Adds unrelated work: state the scope and report optional follow-ups separately.
- Overchecks a small fix: remove inherited generic verification loops; retain
  the checks required for the changed behavior.
- Claims done without testing: name a real check and require disclosure if it
  cannot run. A failed-to-start check is not a pass.
- Misses current facts: identify the volatile facts and required sources; avoid
  a blanket demand to search for every answer.
- Ignores mid-task steering: inspect how user messages are delivered rather than
  treating stronger wording as a cure for a tool-result trust-boundary error.
- Low review recall: inspect vague reporting thresholds before raising effort.
  Separate finding coverage from severity/confidence adjudication where allowed.

Apply the smallest relevant adjustment, then compare the same representative
cases. Do not turn this list into extra instructions in every task packet.
